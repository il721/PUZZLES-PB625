# PUZZLES-PB625: puzzle games for the PocketBook 625

`reader/Puzzle Book.app` is a native touch app (ARM ELF, PocketBook inkview) with a home screen and puzzle **modules**. Modules, ported from https://github.com/il721/puzzles: **Square Rebuses** (`packages/module_rebus`: 15 puzzles + the "Example" sample; `native/puzzlebook/rebus/module01.json` is that repo's puzzle data) **Digit Rebuses** (`packages/module_digit_rebus`: 18 puzzles + "Example"; `native/puzzlebook/digit/module02.json`) **Domino Solitaire** (`packages/module_domino`: 18 puzzles + "Example"; `native/puzzlebook/domino/module03.json`) **Alphabet Labyrinth** (`packages/module_labyrinth`: 18 puzzles + "Example"; `native/puzzlebook/labyrinth/module04.json`) **Squarewords** (`packages/module_squareword`: 17 puzzles + "Example"; `native/puzzlebook/squareword/module05.json`) **Keyword Rebuses** (`packages/module_keyword_rebus`: 17 puzzles + "Example"; `native/puzzlebook/keyword/module07.json`) and **Puzzle games** (`packages/module_playground`: seven small games; `native/puzzlebook/playground/module06.json`). Moved here from il721/PB625 on 2026-10-29 (clean first commit); Wi-Fi, file transfer and the Total Commander plugin stay in il721/PB625.

## Device facts
- PocketBook 625 (Basic Touch 2), firmware R4.4.1585, Linux 3.0.8 armv7l, 6" e-ink touch. Screen 600x800 portrait / 800x600 landscape; the app lays out for both (`EVT_ORIENTATION`).
- Apps run as uid 102 `sreader`, no root. The internal storage `/mnt/ext1` (vfat, no exec bit) is the USB drive; while USB is connected it is unmounted on the reader. Apps live in `<drive>:\applications\*.app`.
- Native apps link against the firmware's `libinkview.so` and libc. The SDK 4.8.1 toolchain targets glibc 2.9; the binary here needs only GLIBC_2.4.
- Confirmed by the user on the reader (2026-10-29): the Puzzle Book build with home screen + Square Rebuses works. The build with Settings and the three languages was tested only in the sandbox. To confirm on the device: Cyrillic text renders (UTF-8 in `DrawString`, LiberationSans), and "System default" picks the reader's language (see the `language setting` line in `puzzlebook.txt`).

## What the app does
- Home: one tile per module (name, "solved / total", description), **no paging and no scrolling: every module is always on the one screen** (`tile_layout()` in `shell.c`: one tile per row while each row stays at least 80 px high, otherwise two columns; tile height stretches to the free space, the description is wrapped by hand and ends in "..." where it does not fit; checked with up to 7 tiles in both orientations), **Random** (random unsolved puzzle from any module, weighted by how many each module has left), `?` help, **Exit**, **Settings** (bottom left; Menu key too).
- Languages and Settings (ported from il721/puzzles, same set: Русский, English, Deutsch): Settings has one section, Language: System default / Русский / English / Deutsch. "System default" reads `language=xx` from the firmware's `/mnt/ext1/system/config/global.cfg` (unknown or missing -> English, like the source). The choice is saved in `/mnt/ext1/puzzlebook.cfg` (`lang=system|ru|en|de`). Settings also has **Transfer progress** (like the source): "Save progress to a file" writes `/mnt/ext1/puzzlebook-progress.json`, "Load progress from a file" reads the same path, shows the file's date and asks Cancel / Load, then merges. The file is the source app's bundle format (`bundleVersion` 1, namespaces `module_rebus`, `module_digit_rebus`, `module_domino`, `module_labyrinth`, `module_squareword`, `module_keyword_rebus` and `module_playground`, one entry per touched puzzle with `cells` (Domino Solitaire: `placed`, a list of `[[r,c],[r,c]]`; Alphabet Labyrinth: `chainA`, `chainZ`, `crosses`, `marks`, lists of `[r,c]`; Squarewords: `filled`, `{"row,col": "letter"}`; Keyword Rebuses: `assignment`, `{"letter": digit}`, an entry with a letter outside the puzzle, a digit above 9 or a letter twice is rejected as a whole: fresh board, solved flag ignored, like the source's `fromJson`; Puzzle games: only solved games, as the game's start position (`positions` / `slots` / `origins`) with an empty `moveStack`, `moveCount` 0 and `bestMoves` - the app rebuilds its board from the moves, so such an entry loads there as "solved, best N moves" on a fresh board; half-played games are not exported because their moves cannot travel and an entry without them would wipe the app's), `solved`, `updatedAt`), so it can be exchanged with the Flutter app in both directions. Merge (`progress.c`, the source's `mergePuzzleEntry` as far as this app tracks it): solved beats unsolved; between two solved copies the lower `bestMoves` wins (present beats absent; without it a tie), so only the Puzzle games ever differ; between two unsolved copies the later `updatedAt` wins (a stamp beats none; older saves without stamps lose to a stamped incoming copy); ties keep the local copy, so loading a file twice changes nothing. Unknown namespaces/puzzles/cells are ignored. Not tracked here: elapsed time, check count, first-solve time (written as 0); for the Puzzle games an incoming half-played entry is ignored (only "solved" and a `bestMoves` not below the proven minimum are taken over, the local board stays). Not ported: sound (the reader has no speaker), dark theme (not sensible on e-ink, would need inkview invert calls not yet checked on the device).
- Opening a tile hands all events to the module until it calls `shell_leave()` (Home button or Back key).
- Digit Rebuses: a 4x4 square of digit cells, every row and column an equation `a op b op c = d` strictly left to right (`+ - x :`, `:` exact, no intermediate value below zero), no givens. Each cell is masked by one of five glyphs that admits a few digits ({0,8,9} {0,6,8} {1,4,7} {2,3} {3,5,9}). The source draws the glyph as a coloured border; on e-ink an empty cell shows the digits its glyph admits (small, grey) and the pad offers only those digits plus Del. Check blackens the cells of broken rules; a full but wrong grid says so. Win = any grid that satisfies all rules. Same buttons and keys as Square Rebuses (List, ?, Home, `<` `>`, Reset twice; Back/Home/Menu keys). Not ported: the timer, check counter and win dialog (neither module has them), the guided tutorial.
- Domino Solitaire: an 8x7 grid of digits 0..6; split it into 28 dominoes so that every value pair 0:0 .. 6:6 appears exactly once. Tap a cell, then an adjacent free cell: they become one tile (grey, no seam). Tap a placed domino to take it back; tapping far away moves the selection, tapping the selected cell again deselects. On the right the 28 pairs: black = already on the board; a pair used twice turns both of its dominoes black (the source tints them red) and the status line says so. Win = every cell covered and no pair twice (any such tiling wins), detected automatically after the last tap (no Check button, as in the source). Same buttons and keys as the other modules (List, ?, Home, `<` `>`, Reset twice). Portrait: board left, pairs in two columns right; landscape: board left, pairs in four columns + status + buttons right. Imported dominoes that do not fit (out of range, not adjacent, overlapping) are skipped. Not ported: the guided tutorial, replay mode (a solved puzzle stays editable like in Digit Rebuses), the timer.
- Alphabet Labyrinth: an 8x8 grid of the 33 letters of the Russian alphabet (each once or twice). Thread one self-avoiding orthogonal path of 33 cells from the top-left cell (А) to the bottom-right one (Я) through every letter exactly once. The path grows from both ends (the source's two chains): tap a cell next to either end to extend it (a cell next to both goes to the top-left chain), tap an end to take a cell back; the path is closed when the two ends touch (then it accepts no more cells, only retraction). Tapping any other cell marks it "must be on the path" (black frame; the source's blue). The source's long press (cross a cell out / cut the path back to a cell) is the **Cross** button here: while it is black, a tap crosses out a free cell or cuts a chain back to the tapped cell (anchors never). Letters that share a letter with the path are dimmed automatically (the source's auto-crosses, derived, never saved); a manual cross is a drawn X. The alphabet under (landscape: beside) the grid shows white = still free, grey with a line = on the path, black = used twice (the source tints it red; the duplicate cells go black too). Letters: Cyrillic in Russian; English and German show the source's stand-in glyphs (A B V G D E = * 3 I J K L M N O P R S T U F X C Q W # & $ @ H Y Z). Win = joined, 33 cells, no letter twice, detected automatically (any such path wins; every puzzle has exactly one). Same buttons and keys as the other modules. Imported lists that do not make a valid board (wrong anchors, jumps, repeats, out of the grid) give a fresh board, like the source's `fromJson`. Not ported: the guided tutorial, replay mode, the timer.
- Square Rebuses: each row `a op b op c op d = r` evaluated strictly left to right (`+ - x :`, `:` exact), numbers 1..999 without leading zero, column j sums to the result of row j, the summary row repeats the four results and totals them. Win = any grid that satisfies all rules. Tap a box, tap a digit; Check turns broken rules into black boxes; Del, Reset (tap twice), `<` `>` puzzles, List, `?` rules, Home. Keys: Back = leave screen/exit, Home or Menu key = straight to the home screen, Prev/Next = puzzle.
- Squarewords: an n x n grid (5, 6 or 7) built around an n-letter Cyrillic keyword; row 0 is the keyword, a few more cells are printed (grey). Fill the rest so every row, every column and both main diagonals hold each keyword letter exactly once. Tap a free cell (thick frame, grey), then a letter button below the grid (landscape: beside it); the **x** button empties the selected cell; tapping the selected cell again or a printed cell drops the selection. A letter that repeats in a line is allowed but turns both cells black (the source: red) and the status line says so; a letter button is grey when all n copies are on the board and black when it is the letter of the selected cell. Win = grid full and no repeat, detected automatically (any such grid wins; every puzzle has exactly one). Letters stay Cyrillic in every language (as in the source). The source's long press (clear) is the eraser button. Same buttons and keys as the other modules. Imported letters on printed cells, outside the grid or outside the keyword are skipped. Not ported: the guided tutorial, replay mode, the timer.
- Keyword Rebuses: a 3x3 cross of words built from ten different Cyrillic letters; every letter is one digit (same letter = same digit, different letters = different digits), a word of 2+ letters never starts with 0. Row 1 is `a x b = c`, rows 2 and 3 `a + b = c`; columns left to right `+`, `x`, `-` (top minus middle). The ten letters ordered by their digits 0..9 spell the book's keyword, shown in the status line on a win. Tap a letter (in the grid, the letter bank under it, or a strip slot that holds one), then a digit on the pad (two rows in portrait, 4 x 3 on the right in landscape); **Del** removes the selected letter's digit; tapping the selected letter again deselects it. The bank lists the ten letters in order of first appearance (not keyword order, which would give the answer away) and shows each letter's digit big once it has one (letter small in the corner); the strip under it has ten slots 0..9 showing which letter holds each digit. A digit on two letters turns both letters and the strip slot black (the source: red) and the status line says so; a word of 2+ letters whose first letter holds 0 turns that letter black; an equation whose letters all have digits and that fails turns its `op` and `=` signs black (partial equations stay neutral, like the source). Pad digits some letter holds are grey, the selected letter's digit is black. Win = all ten letters set, all digits distinct, no leading zero, all six equations hold (any such assignment wins; every puzzle has exactly one, checked by exhaustive search), detected automatically. Same buttons and keys as the other modules (List, ?, Home, `<` `>`, Reset twice). Not ported: the guided 10-step tutorial, the timer, the win dialog (the keyword is in the status line instead).
- Puzzle games: seven small unrelated games, one "puzzle" each (the list shows them with their status; `<` `>` switch). Every game has Undo (replays the recorded moves), Reset (tap twice; keeps "solved" and the best move count), the move counter, the proven minimum where there is one, and `?` shows the game's rules. A win is detected automatically; the status line then says "Solved in N moves!" (and "That is the minimum!" when N equals the proven minimum), the best move count is kept. The rule engines (`pg_core.c`) are the source's, boards and tiles copied as they are. **Eight chips** (minimum 28): chips 1-8 on the tips of an eight-pointed star slide along straight lines over free spots; reverse the ring, the centre free again. **Cats and dogs** (32): three cats (black C) and three dogs (grey D) swap sides of a 13-node park, one step per move, and a move that would put a cat next to a dog is never offered. **Hourglass** (26): fifteen pieces from the upper triangle to the lower one; a step to a free neighbour or a checkers-style jump, a cascade of jumps by one piece is one move and every landing of the cascade is offered (the source's rule). Eight chips also shows a small picture of the goal (chips 1-8 on their final tips, the centre free): bottom left with the status text to its right in portrait, at the bottom of the right column in landscape. For these three: tap a piece (a ring marks it), then one of the marked places (a ring with a dot); the piece again lets go. **Three of each**: nine 3x3 tiles with circles (red = grey, white = ring, black = solid) form a 9x9 square with exactly one circle of each colour in every row, column and diagonal. **Patterns 5x5** / **4x4**: 25 / 16 tiles (2x2 cells each, a line through every cell) form one closed line that never crosses itself. For the tile games: the tray holds the tiles that are not laid (a laid tile leaves a faint gap); tap a tray tile to pick it up, tap it again or press **Rotate** to turn it, then tap an empty place; tap a laid tile to select it, then **Rotate** (or a second tap) turns it in place and **To tray** takes it back; every placing, turning and taking back counts as a move (no minimum, as in the source); when the board is full but wrong the status line names the reason (an open line end, several loops, a row/column/diagonal that is not right). **Swap the squares** (32): twelve P-shaped blocks fill a 16x8 box; a block slides any distance through free space round corners (one move); swap the two grey blocks at the top with the two black ones at the bottom while all others come home. Tap a block (thick outline), dots mark every place it can go (the dot sits on the cell where the block's first cell would land), tap a dot to see a grey ghost of the landing place, tap it again to move (the source's press-and-hold preview, which the reader's touch events do not offer). Moves are kept for Undo and in the save file (at most 1500 per game). Same top buttons and keys as the other modules. Not ported: the solution replay ("Show solution"), the timer and the win dialog, and half-played games do not travel in the progress file.
- Files on the drive: progress `/mnt/ext1/rebus.sav`, `/mnt/ext1/digit.sav`, `/mnt/ext1/domino.sav`, `/mnt/ext1/labyrinth.sav`, `/mnt/ext1/squareword.sav`, `/mnt/ext1/keyword.sav` and `/mnt/ext1/playground.sav` (Puzzle games: first line `v1 <last game>`, then one line per game: solved flag, best move count (0 = none), ms timestamp, the number of moves and the moves themselves, each packed into one number (`pg_pack`: kind, a, b, c); the board is rebuilt by replaying them, a damaged list resets that board but keeps solved and best; Keyword Rebuses: solved flag, ten chars = the digit of each letter in bank order or `-`, timestamp; Squarewords: solved flag, n*n chars, `.` = empty or printed, else the keyword letter's index `0`..`6`, timestamp; one line per puzzle: solved flag, grid (Domino: 56 chars, `R` = first half of a horizontal domino, `D` = of a vertical one), ms timestamp of the last change; Labyrinth: solved flag, chain A, chain Z, crosses, marks (one char per cell, `'0'` + row*8+col, `-` = none), timestamp; older lines without the timestamp still load), the transfer file `/mnt/ext1/puzzlebook-progress.json`, settings `/mnt/ext1/puzzlebook.cfg`, debug log `/mnt/ext1/puzzlebook.txt` (screen size, orientation, language setting and the language actually shown).
- Install: copy `reader/Puzzle Book.app` to `<drive>:\applications`, eject, open it from the Applications menu. Delete an old `Square Rebuses.app` there.

## Layout
- `native/puzzlebook/`: `shell.h` (module interface + shared helpers), `shell.c` (home, settings, routing, random), `i18n.c/.h` (languages, setting, `tr()`), `progress.c/.h` (progress file: JSON writer/reader, merge), `ui.c`, `modules.c` (registry), `rebus/`, `digit/`, `domino/`, `labyrinth/`, `squareword/`, `keyword/` and `playground/` (modules; `playground/pg_core.c` the seven rule engines, `module_playground.c` the screens), `example/` (template, not registered), `Makefile`, `README.md` (how to add a module).
- `tools/`: `gen-rebus-data.py` (module01.json -> `rebus_data.h`), `gen-digit-data.py` (module02.json -> `digit_data.h`), `gen-domino-data.py` (module03.json -> `domino_data.h`), `gen-labyrinth-data.py` (module04.json -> `labyrinth_data.h`), `gen-squareword-data.py` (module05.json -> `squareword_data.h`), `gen-keyword-data.py` (module07.json -> `keyword_data.h`), `gen-playground-data.py` (module06.json -> `playground_solutions.h`, host test only), `test-playground-gen.py` (writes the Puzzle games UI scripts from the geometry the test build logs), `fake-inkview/` (stand-in `inkview.h` that draws to SVG), `test-rebus-ui.sh`, `test-modules1.c`/`test-modules2.c` (test registries).
- `reader/Puzzle Book.app`: the built binary (marked binary in `.gitattributes`).

## Build
The SDK is not committed (about 1.7 GB): `git clone --depth 1 https://github.com/pocketbook/SDK_481 sdk` (default branch 5.5: gcc 4.8.1 i386-static cross compiler, glibc 2.9 sysroot, `libinkview.so`). Then:

```
make -C native/puzzlebook SDK=$PWD/sdk
```

writes `reader/Puzzle Book.app` (stripped). Check `readelf -V "reader/Puzzle Book.app"` shows only GLIBC_2.4 and `readelf -d` only `libinkview.so` and `libc.so.6`. In the cloud sandbox the compiler is a downloaded binary: the user must allow running it once.

## Working loop
Claude changes the code, runs the tests, rebuilds the binary and commits it. The user copies it to the reader, tries it, and pastes `puzzlebook.txt` plus a description of what the screen did.
